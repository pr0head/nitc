# NITC — архитектура клиента

Самостоятельный веб-клиент карты Netgress поверх официального read-only Map API
(`docs/NETGRESS_MAP_API.md`). Цель — современный, отзывчивый интерфейс и
переосмысленный UX при строгом соблюдении контракта «только чтение».

## Принципы
- Тонкие слои, минимум фреймворка — движок карты и UI остаются заменяемыми.
- Весь сетевой код изолирован; бизнес-правила контракта (направление линка,
  геометрия поля, 180-й меридиан, геодезия) — в адаптере, не в транспорте.
- Строгое уважение к бюджету API и к приватности токена.

## Слои
```
src/
  api/        transport: fetch+Bearer, ETag-кеш, AbortController, generation-guard,
              маппинг ошибок (HTTP+error.code), соблюдение Retry-After
  adapter/    map/portal/activity JSON -> внутренняя модель; faction-normalize;
              линк по source_portal_id; поле = 3 вершины; антимеридиан/геодезия
  map/        движок + отрисовка (порталы, линки, поля), canvas-оверлей подсветки
              (дуги/текст/площади), правила подсветки, геодезия
  game/       расчёты карточки портала по классическим правилам (дальность линка,
              защита, хаки/кулдаун, энергия, AP за снос); эффекты модов — из
              серверной спецификации мода
  ui/         меню плашки, слои/фильтры, карточка портала, COMM, диалоги
  plugins/    избранное, рисование (IITC DrawTools JSON), планы рисунков,
              трекер агентов (пины и следы по событиям COMM)
  state/      сессия, prefs, избранное, треки агентов, шина событий (bus) +
              «один инструмент карты»
```

Раскладка (десктоп) повторяет привычную по IITC: слева инструменты карты, справа
информация. Слева сверху — плашка профиля с меню «☰ NITC» (плагины: рисование,
избранное; аккаунт), всегда поверх панелей; под ней — панель рисования, если
включена. Справа сверху — карточка портала, кнопка слоёв сдвигается левее неё.
Снизу слева — COMM (развёрнутый перекрывает панель рисования), снизу справа —
«где я», зум, статус карты.

Фичи общаются через `state/bus.js` (`portalClick`, `openPortal`,
`favoritesChanged`, `drawChanged`/`drawLoad`, `toolActivated`, `commEvents`,
`focusAgent`/`agentFocus`), а не импортом
друг друга. Отложенные идеи фич (в т.ч. ждущие API) — `docs/future-ideas.md`.

## Внутренняя модель
```
Portal  { id, name, lat, lng, faction, level, resonatorCount, xm:{cur,max} }
Detail  extends Portal { photoUrl, owner, resonators:[8|null], mods:[4|null] }
Reso    { slot, level, owner, xm:{cur,max} }
Mod     { slot, owner, spec:{ kind,type,name,rarity, ...stats } }
Link    { id, faction, source, a:{id,lat,lng}, b:{id,lat,lng} }   // source = source_portal_id
Field   { id, faction, mu|null, v:[{id,lat,lng}×3] }
Event   { id:int64, kind, time, actorId, nickname, faction, portals:[{id,name,lat,lng}], mu|null }
```
Правила из контракта, которые адаптер обязан соблюдать:
- faction: `blue`/`green`/`neutral` → наша нормализация (напр. res/enl/neutral + отображаемые имена).
- нейтральность определяется `faction`, НЕ нулевым уровнем.
- направление линка — по `source_portal_id`, не по порядку вершин.
- `field.mu === null` ≠ 0; свой MU не вычисляем.
- вершины линков/полей самодостаточны — не требуем их наличия в `portals`;
  вершины без записи в `portals` становятся «угловыми» порталами (`corners`:
  id, координаты, фракция линка/поля) — их рисуем мелкими точками, клик
  открывает карточку по id.
- `truncated`/`portals_omitted`/LOD обрабатываем независимо; отсутствие объекта
  в усечённом ответе НЕ означает его уничтожение.
- порядок резонаторов: слот 0 = север, по часовой, шаг 45° (без IITC-преобразования).

## Поток данных
1. Логин → токен `scope: intel:read` в `localStorage` (перезагрузка не
   разлогинивает); выход — отзыв сессии и сброс.
2. `moveend`/zoom → debounce ~350 мс → `GET /map` (bbox+целый zoom), abort старого,
   generation-guard, ETag/304.
3. Рендер по модели; выбор портала → `GET /portals/{id}` (ETag/304, прежний
   запрос отменяется).
4. COMM: первая страница без курсора (50 новых→старых); `cursor=next` в прошлое;
   `after` для новых (старые→новые), дочитывать при `more=true`; сброс курсоров при смене bbox.
5. Периодическое обновление ~30 с; пауза на скрытой вкладке; на 401 — сброс сессии и вход.
6. 429 → код `rate_limited` и `Retry-After` показываются в статусе карты и COMM.

## Состояние фич
Реализованное перечислено в `README.md` («Возможности»); отложенные идеи — в
`docs/future-ideas.md`.

Доступно из снимка карты массово: уровень, фракция, энергия портала. Владелец,
резонаторы и моды — только в карточке (`/portals/{id}`), поэтому подсветка «по
владельцу» массово по снимку невозможна (нет `owner` в summary).

## Движок карты — Leaflet
Выбран **Leaflet** (проверен на этом же классе задач — интел-оверлеи поверх
тайлов). API движко-независим (отдаёт вершины), поэтому `adapter/` изолирует
выбор, и при желании движок можно заменить. Подложки: Yandex (по умолчанию,
`projection=web_mercator` для выравнивания в EPSG:3857), Yandex гибрид, Google,
Google гибрид, OSM. Спутник Яндекса существует только в EPSG:3395, поэтому на
время Yandex-гибрида карта переключается в EPSG:3395 (все слои строятся по
lat/lng и перепроецируются вместе с ней).

## Сборка и запуск
Vite + vanilla JS (без тяжёлого фреймворка).
- `npm install`
- `npm run dev` — дев-сервер на `http://localhost:5173`, HMR.
- `npm run build` → статика в `dist/`; `npm run preview` — проверка сборки.
- Прод-база пути: `/nitc/` (GitHub Pages). Переопределяется `VITE_BASE`.
- Деплой: `.github/workflows/deploy.yml` — на каждый push в `main` (или вручную)
  `npm ci && npm run build` и публикация `dist/` на GitHub Pages
  (`https://pr0head.github.io/nitc/`). В настройках репозитория один раз:
  Settings → Pages → Source: GitHub Actions.

### CORS и как его обходим
Сервер Netgress пускает по CORS только перечисленные в контракте origin: два
интел-origin Ingress и наш `https://pr0head.github.io` (добавлен 26.10.2026).
localhost среди них нет (иначе `403 origin_denied`). Запросы **без** Origin
(не из браузера) проходят с валидным токеном. Отсюда:
- **dev:** Vite проксирует `/api` → upstream на стороне сервера и срезает
  заголовки `Origin`/`Referer` → для Netgress это запрос без Origin → проходит.
  Проверено: `GET /api/v1/intel/map` отдаёт `401` (не `403`), с токеном — данные.
- **prod (статика, APK):** прокси нет, запросы идут напрямую со страницы на
  разрешённом origin. Другой домен потребует нового согласования с владельцем
  (или `VITE_API_BASE` на согласованный прокси).
- Отказ по CORS браузер выдаёт как сетевую ошибку; клиент отличает его
  пробным `no-cors`-запросом (`api/client.js`) и пишет «сервер отклонил запрос».
- Базовый адрес API: `src/config.js` — `/api` в dev, `VITE_API_BASE` или прямой
  origin в prod.

## Android-приложение
`android/` — оболочка без зависимостей: одна Activity (Java) с полноэкранным
WebView, открывающим `https://pr0head.github.io/nitc/`. Карта грузится с Pages,
поэтому APK пересобирается только при изменении самой оболочки. Origin в WebView
тот же, что у сайта, — отдельного CORS-разрешения не нужно.
- Внутри остаются только страницы `/nitc/`; прочие ссылки открывает системный браузер.
- `localStorage` включён (сессия, настройки, избранное, планы).
- Геопозиция: запрос страницы → Android-разрешение на местоположение → ответ странице.
- «Назад» — история WebView, затем выход; поворот экрана не перезагружает карту.
- Отступы под системные панели (edge-to-edge с Android 15).

Сборка — `.github/workflows/android.yml` (AGP 9.4, Gradle 9.8, JDK 17; локально
Android SDK не нужен): тег `v*` → подписанный APK в GitHub Release; ручной запуск →
APK артефактом сборки (без ключа — debug-подпись, только для проверки). Если с
прошлого тега `v*` не менялись ни `android/`, ни сам workflow, APK не собирается:
к релизу прикладывается APK прошлого релиза как есть, так что в последнем
релизе APK есть всегда. Ключ
подписи — в секретах репозитория (`ANDROID_KEYSTORE_B64`, `ANDROID_KEYSTORE_PASSWORD`,
`ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`). Потеря ключа = установленное
приложение нельзя обновить, только переустановить.

Для установки без APK сайт — PWA: `public/manifest.webmanifest` и иконки.
