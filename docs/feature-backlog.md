# Бэклог фич на уже доступных данных

Что можно построить на том, что Map API отдаёт **уже сейчас** (в отличие от
`future-ideas.md`, где фичи ждут новых эндпоинтов). Источник контракта —
`docs/NETGRESS_MAP_API.md`. Данные проверены на живом API 25.10.2026.

Статусы: ✅ сделано · ⬜ не начато.

## Данные, которые ещё не используются

| Данные | Где | Что в них есть |
| --- | --- | --- |
| Журнал COMM | `GET /v1/intel/activity` | события `capture`, `neutralize`, `link_create/destroy`, `field_create/destroy`, `first_link`; ник и фракция автора, время, упомянутые порталы с координатами, MU полей; курсоры в прошлое (`next`) и для новых (`after`, `more`) |
| MU полей | `fields[].mu` в `/map` | подтверждённый сервером MU; `null` = ещё не рассчитан (не ноль) |
| Метаданные LOD | `lod` в `/map` | `min_link_length_m` — порог длины скрытых линков; `has_portals` |
| Направление линка | `source_portal_id` | откуда построен линк |

Уже используются: спецификация модов (характеристики в карточке) ✅, ники
владельцев резонаторов/модов/портала прямо в карточке ✅, флаги `truncated` и
`portals_omitted` в строке статуса ✅, входящие/исходящие линки в карточке ✅.

## Фичи

### COMM — главный кандидат

1. ✅ **Лента COMM** — панель событий видимой области: первая страница (50
   новых), подгрузка старых по `next`, опрос новых по `after` (с дочитыванием
   при `more=true`), сброс курсоров при смене области, дедупликация по `id`.
   Фильтры: тип события, фракция. Клик по событию → центр карты на портале и
   его карточка. Обновление ~30 с, пауза на скрытой вкладке.
2. ✅ **MU в ленте** — `+N MU` / `−N MU` у создания/уничтожения полей. `mu`
   может появиться позже: периодически перечитывать первую страницу и
   обновлять по `id`.
3. ✅ **Событие на карте** — наведение на запись подсвечивает её порталы, а
   для линка/поля — их геометрию.
4. ⬜ **Трекер агента** — путь агента по его последним событиям: точки
   порталов, время, линия между ними; фильтр по нику (клик по нику в ленте).
5. ⬜ **История портала в карточке** — последние события с этим порталом из
   загруженной ленты области (не полная история: её API не отдаёт).
6. ⬜ **Сигнал по избранному** — событие на избранном портале (захват,
   нейтрализация) → отметка в ленте и бейдж на кнопке избранного.

### MU полей

7. ✅ **MU на поле** — отдельная галка «MU» в блоке «Подсветка полей» (по
   умолчанию выключена, как и «Площадь»); при обеих — «площадь · MU». `null`
   показывается как «? MU», не как 0.

### Карта

8. ✅ **Статус карты** — справа внизу: что сейчас показано по каждому слою
   (порталы / «скрыты — приблизьте», линки «все» или «> N м» из
   `lod.min_link_length_m`, «обрезано» по `truncated`) и состояние загрузки.
9. ⬜ **Направление линков** — опционально в слоях: стрелка или градиент от
   исходного портала.

## Ограничения, которые надо соблюдать

- `distance_m` в событиях всегда `0` — это не расстояние, не показывать.
- Позиция события — опорный портал; остальные порталы события могут быть за
  экраном.
- Имена и координаты в событиях — исторические: портал мог исчезнуть или
  сменить фракцию; открытие обрабатывает 404.
- Свой MU не вычисляем — только серверный `mu`.
- Бюджет 120 запросов/мин общий для карты, карточек и COMM.
