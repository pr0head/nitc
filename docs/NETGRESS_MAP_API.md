# Netgress API: полный справочник для разработчиков карт

Состояние контракта: **29 октября 2026 года**. Версия справочника: **1.3.0**. Версия маршрутов: `/v1`; версия снимка карты и карточки: `schema: 1`.

Этот API позволяет создать собственную карту Netgress: показывать порталы, направленные линки, поля, карточки порталов, журнал игровых действий, профили агентов, собственные ключи и инвентарь, мировой счёт MU. Он не зависит от IITC: можно использовать собственный движок карты. Все данные читаются из действующего игрового мира Netgress; отдельной копии мира для карты нет.

**API предназначен только для чтения.** Через него нельзя перемещать игрока, устанавливать резонаторы или моды, создавать линки, атаковать, изменять инвентарь.

Машиночитаемое описание: [OpenAPI 3.1](netgress-map-api.openapi.json). Практический пример существующего клиента: [Netgress IITC](../iitc/netgress-iitc.user.js).

## Подключение и доступ из браузера

Основной адрес:

```text
https://api.netgress.ru
```

Прежний адрес `https://netgress.glubina.org` пока продолжает работать. Альтернативный опубликованный адрес — `https://ingress.worldofton.ru`. Для одного клиента выбирайте один адрес и привязывайте сохранённую сессию и кеш к нему.

### Важное ограничение CORS

**Произвольный сторонний сайт сейчас не может напрямую обращаться к API из браузера.** Сервер разрешает только следующие `Origin`:

```text
https://intel.ingress.com
https://intel-x.ingress.com
https://pr0head.github.io
```

Для новой веб-карты на отдельном домене нужно заранее согласовать доступ с владельцем Netgress и добавить точный origin в серверный список разрешений. Это относится также к `localhost` и к страницам, открытым как локальный HTML-файл: их origin не разрешён автоматически. Настоящая документация сама по себе не расширяет список доступа.

Серверные HTTP-клиенты и консольные программы могут обращаться без `Origin`, но всё равно обязаны иметь действительный токен. CORS не заменяет авторизацию. Не подделывайте разрешённый origin и не отключайте защиту браузера. Если проект использует собственный сервер, заранее определите с владельцем API схему интеграции и хранения пользовательских сессий.

Для разрешённых origins:

| Параметр | Значение |
| --- | --- |
| Методы CORS | `GET, POST, DELETE, OPTIONS` |
| Разрешённые заголовки | `Authorization, Content-Type, If-None-Match` |
| Доступные JavaScript заголовки ответа | `ETag, Retry-After` |
| Cookies | Не используются; для `fetch` задавайте `credentials: "omit"` |

### Маршруты

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/v1/auth/intel/login` | Вход в существующий аккаунт, выдача read-only токена |
| `GET` | `/v1/intel/map` | Снимок видимой области карты |
| `GET` | `/v1/intel/portals/{id}` | Карточка конкретного портала |
| `GET` | `/v1/intel/activity` | Журнал действий в области карты |
| `GET` | `/v1/intel/me` | Профиль владельца текущего Intel-токена |
| `GET` | `/v1/intel/agents/{id}` | Публичная карточка агента по UUID |
| `GET` | `/v1/intel/agents?nickname=…` | Публичная карточка по точному нику без учёта регистра |
| `GET` | `/v1/intel/me/keys?cursor=…` | Только собственные ключи, включая содержимое капсул |
| `GET` | `/v1/intel/me/inventory` | Только собственная сводка предметов по виду и уровню |
| `GET` | `/v1/intel/score` | Мировой MU-баланс фракций |
| `GET` | `/v1/intel/rating?kind=links&cursor=…` | Рейтинг агентов как в игровом клиенте, по 25 строк |
| `DELETE` | `/v1/intel/session` | Отзыв текущего токена |

## Быстрый старт

Нужен существующий аккаунт Netgress с подтверждённым email и созданным игровым профилем. Аккаунт Ingress не подходит. Примеры ниже используют Bash и `curl`; в PowerShell вызывайте `curl.exe` и адаптируйте синтаксис переменных/переноса строк.

Создайте локальный `login.json` с **собственными** учётными данными. Не добавляйте этот файл в репозиторий:

```json
{
  "email": "developer@example.com",
  "password": "your-password"
}
```

Получите токен:

```bash
curl --silent --show-error --fail-with-body \
  -X POST 'https://api.netgress.ru/v1/auth/intel/login' \
  -H 'Content-Type: application/json' \
  --data-binary @login.json
```

Сохраните `token` из ответа в переменную `NETGRESS_TOKEN`, затем запросите карту:

```bash
curl --silent --show-error --fail-with-body --compressed \
  -H "Authorization: Bearer ${NETGRESS_TOKEN}" \
  'https://api.netgress.ru/v1/intel/map?bbox=38.95,44.95,39.05,45.05&zoom=16'
```

Откройте карточку одного из **полученных** порталов, подставив его UUID:

```bash
curl --silent --show-error --fail-with-body --compressed \
  -H "Authorization: Bearer ${NETGRESS_TOKEN}" \
  "https://api.netgress.ru/v1/intel/portals/${PORTAL_ID}"
```

Все UUID, никнеймы и данные в JSON-примерах документа вымышлены. Курсоры в примерах — обозначения; рабочие значения нужно получать из ответов сервера.

## Авторизация и сессия

### Вход

```http
POST /v1/auth/intel/login
Content-Type: application/json
```

Тело — JSON с полями `email` и `password`. Неизвестные серверу поля отклоняются. Максимальный размер тела — 4096 байт. Сервер проверяет подтверждение email, пароль и наличие игрового профиля. Вход не создаёт игровую сессию Android.

Успешный ответ — **200**:

```json
{
  "token": "ngi_<opaque-secret>",
  "expires_at": null,
  "scope": "intel:read"
}
```

Токен считайте непрозрачной строкой. В текущей реализации это отдельный секрет с префиксом `ngi_`, а не JWT. Не извлекайте из него пользователя или время жизни.

Новые сессии бессрочные: `expires_at: null`. Для них нет процедуры refresh и нет необходимости повторять вход каждые восемь часов. Сохраняющий сессию клиент хранит токен, а не пароль. Отзыв токена, сброс пароля или очистка локального хранилища могут потребовать нового входа.

В каждый защищённый запрос передавайте:

```http
Authorization: Bearer <token>
```

Не передавайте токен в URL, не помещайте его в общий кеш, логи, публичные конфиги или код приложения. Ограничение `intel:read` не делает секрет публичным.

### Выход

```http
DELETE /v1/intel/session
Authorization: Bearer <token>
```

Успешный ответ — **204**, без JSON-тела. После подтверждённого выхода удалите локальный токен и пользовательский кеш. При повторном запросе с уже отозванным токеном возможен **401**. При сетевой ошибке нельзя считать серверный отзыв подтверждённым.

Сброс пароля аккаунта также отзывает его Intel-сессии. Read-only токен не принимается игровыми маршрутами `/v1/world`, `/v1/activity`, `/v1/me` и маршрутами действий.

## Координаты и идентификаторы

- Система координат — WGS84, градусы. `position` имеет вид `{ "latitude": 45.0, "longitude": 39.0 }`, без округления до E6.
- `bbox` имеет порядок **west,south,east,north**, то есть долгота, широта, долгота, широта.
- Долгота — от −180 до 180, широта — от −90 до 90, `south <= north`. `NaN`, бесконечность и пропущенные координаты недопустимы. Для Web Mercator ограничивайте широту примерно ±85.05112878° на стороне клиента.
- `west > east` обозначает область через 180-й меридиан: `bbox=170,-20,-170,20`. Полный мир задаётся `-180,-85,180,85`; не превращайте его в bbox нулевой ширины при нормализации долгот.
- Идентификаторы порталов, линков и полей — UUID-строки. Используйте их как стабильные ключи объектов, не как координаты. IITC GUID и его суффиксы — адаптация конкретного клиента; этому API они не нужны.
- GeoJSON использует массив координат **[longitude, latitude]**. Не перепутайте его с порядком аргументов некоторых картографических библиотек.
- Текстовые значения, включая имя портала и никнейм, вставляйте как текст, а не как HTML.

## Снимок карты

```http
GET /v1/intel/map?bbox=38.95,44.95,39.05,45.05&zoom=16
```

Оба параметра обязательны. `zoom` — целое число от **0 до 22**. Ответ **200** — согласованный снимок одной области:

```json
{
  "schema": 1,
  "lod": { "zoom": 16, "min_link_length_m": 0, "has_portals": true },
  "portals_omitted": false,
  "truncated": {},
  "portals": [
    {
      "id": "00000000-0000-4000-8000-000000000001",
      "name": "Example North",
      "position": { "latitude": 45.001, "longitude": 39.0 },
      "faction": "blue",
      "level": 1,
      "resonator_count": 1,
      "current_xm": 1250,
      "max_xm": 2500
    }
  ],
  "links": [
    {
      "id": "00000000-0000-4000-8000-000000000011",
      "faction": "blue",
      "source_portal_id": "00000000-0000-4000-8000-000000000001",
      "vertices": [
        { "id": "00000000-0000-4000-8000-000000000001", "position": { "latitude": 45.001, "longitude": 39.0 } },
        { "id": "00000000-0000-4000-8000-000000000002", "position": { "latitude": 45.0, "longitude": 39.002 } }
      ]
    }
  ],
  "fields": [
    {
      "id": "00000000-0000-4000-8000-000000000012",
      "faction": "blue",
      "mu": null,
      "vertices": [
        { "id": "00000000-0000-4000-8000-000000000001", "position": { "latitude": 45.001, "longitude": 39.0 } },
        { "id": "00000000-0000-4000-8000-000000000002", "position": { "latitude": 45.0, "longitude": 39.002 } },
        { "id": "00000000-0000-4000-8000-000000000003", "position": { "latitude": 45.0, "longitude": 38.998 } }
      ]
    }
  ]
}
```

Пример иллюстрирует независимость вершин графа от массива `portals`: координаты концов линков и углов полей уже находятся в `vertices`. Не требуйте наличия каждого такого портала в `portals`, иначе карта потеряет часть графа.

### Поля ответа

| Поле | Тип | Смысл |
| --- | --- | --- |
| `schema` | integer | Сейчас `1`; проверяйте совместимость |
| `lod.zoom` | integer | Принятый сервером zoom |
| `lod.min_link_length_m` | integer | Порог длины линка в метрах, `0` — все линки |
| `lod.has_portals` | boolean | Доступна ли самостоятельная массовая загрузка порталов |
| `portals_omitted` | boolean | Порталы намеренно пропущены из-за LOD, а не из-за ошибки |
| `truncated` | object | Флаги превышения лимита отдельных массивов |
| `portals`, `links`, `fields` | array | Даже при отсутствии данных возвращаются массивы |

Портал содержит `id`, `name`, `position`, `faction`, `level`, `resonator_count`, `current_xm`, `max_xm`. Фракции: `blue`, `green`, `neutral`. Уровень берите из `level`; нейтральность определяется `faction`, а не нулевым уровнем. Фото, владелец и слоты загружаются отдельно карточкой.

Линк содержит две вершины. **Направление задаёт `source_portal_id`, а не порядок `vertices`.** Найдите исходную вершину по UUID, вторая будет конечной.

Поле содержит три вершины. `mu` — подтверждённый сервером результат либо `null`, если расчёт ещё недоступен. `null` не означает ноль. Не вычисляйте и не выдавайте собственную оценку за серверный MU.

### Детализация по масштабу

| `zoom` | Линки | Самостоятельные порталы |
| --- | --- | --- |
| 0–4 | Длиннее 200 000 м | Нет |
| 5–6 | Длиннее 60 000 м | Нет |
| 7 | Длиннее 10 000 м | Нет |
| 8 | Длиннее 5 000 м | Нет |
| 9–10 | Длиннее 2 500 м | Нет |
| 11 | Длиннее 800 м | Нет |
| 12 | Длиннее 300 м | Нет |
| 13–14 | Все | Нет |
| 15–22 | Все | Да |

При ненулевом пороге сравнение строгое: **длина > порога**. Фильтрация выполняется сервером до ограничения размера массива. У полей нет отдельного минимального размера в этой таблице: они продолжают отбираться по пересечению с областью.

Для обычной карты с целочисленным zoom можно передавать его напрямую. Если движок использует дробный zoom, явно выберите целый уровень в своём адаптере. IITC-клиент передаёт свой эффективный *data zoom*, который может объединять соседние масштабы; стороннему клиенту не нужно повторять внутренний кеш IITC. Ориентируйтесь на возвращённый `lod`.

### Пересечение и неполные ответы

Порталы отбираются по попаданию точки в bbox. Линки и поля — по пересечению своей серверной геометрии с bbox. Поэтому линк или поле могут присутствовать, даже когда их вершины находятся за экраном.

Лимиты одного ответа:

| Коллекция | Максимум |
| --- | ---: |
| `portals` | 3000 |
| `links` | 2000 |
| `fields` | 2000 |

Если лимит превышен, появляется соответствующий флаг:

```json
{ "truncated": { "portals": true, "links": true } }
```

Отсутствующий флаг равнозначен `false`; не ожидайте обязательного наличия всех трёх ключей. Для карты **нет курсора продолжения**. Просите приблизить область или разбивайте запрос на меньшие bbox в пределах бюджета запросов; при объединении удаляйте дубликаты по ID. Не обещайте полноту региона, пока все его части не получены без `truncated`.

На дальних масштабах приоритет имеют длинные линки и крупные поля; на близких не следует полагаться на порядок коллекций. Отсутствие объекта в ограниченном ответе, смена LOD или выход объекта за bbox **не доказывают его уничтожение**. Снимок описывает текущую область, а не журнал удалений всего мира.

API возвращает вершины, а не GeoJSON или готовые линии отрисовки. Геодезические линии и разбиение графа через 180-й меридиан реализуйте в своём картографическом адаптере; наивная линия через всю плоскую карту даст неверное изображение.

## Подробности портала

```http
GET /v1/intel/portals/00000000-0000-4000-8000-000000000001
```

Портал можно запросить независимо от zoom и наличия его в последнем массиве `portals`. Ответ **200** содержит все поля краткого портала и дополнительные данные:

```json
{
  "schema": 1,
  "id": "00000000-0000-4000-8000-000000000001",
  "name": "Example North",
  "position": { "latitude": 45.001, "longitude": 39.0 },
  "faction": "blue",
  "level": 1,
  "resonator_count": 1,
  "current_xm": 1250,
  "max_xm": 2500,
  "photo_url": "",
  "owner": "ExampleAgent",
  "resonators": [
    { "slot": 0, "level": 4, "current_xm": 1250, "max_xm": 2500, "owner": "ExampleAgent", "distance_m": 25.0 },
    null, null, null, null, null, null, null
  ],
  "mods": [
    {
      "slot": 0,
      "owner": "ExampleAgent",
      "spec": {
        "kind": "shield_common",
        "type": "shield",
        "name": "Portal Shield",
        "rarity": "common",
        "xm_cost": 400,
        "recycle_xm": 40,
        "mitigation": 30,
        "stickiness": 0,
        "range_multiplier": 0,
        "link_defense": 0,
        "outgoing": 0,
        "heat": 0,
        "hacks": 0,
        "force": 0,
        "strike": 0,
        "hit_bonus": 0,
        "drop_chance": 0.02
      }
    },
    null, null, null
  ],
  "planning": {"fully_deployed":false,"max_link_range_m":0,"incoming_links":0,"outgoing_links":0,"outgoing_limit":8}
}
```

| Поле | Особенности |
| --- | --- |
| `owner` | Никнейм захватившего портал, не UUID. `null` для нейтрального/неустановленного владельца |
| `photo_url` | Может быть пустой строкой; предусмотрите заглушку и ошибку загрузки изображения |
| `resonators` | Всегда 8 элементов, индексы 0–7; пустой слот — `null` |
| `resonators[].owner` | Никнейм владельца конкретного резонатора |
| `resonators[].distance_m` | Расстояние в метрах от центра портала до сохранённой позиции этого резонатора; не расстояние до игрока |
| `mods` | Всегда 4 элемента, индексы 0–3; пустой слот — `null` |
| `mods[].owner` | Никнейм установившего мод |
| `mods[].spec` | Действующая серверная спецификация мода; используйте `name` для подписи, `kind` как ключ |

Слоты резонаторов Netgress идут от севера по часовой стрелке с шагом 45°: 0 — север, 1 — северо-восток, 2 — восток, …, 7 — северо-запад. Для схемы IITC используется преобразование `(2 - slot + 8) % 8`; для собственной схемы оно не требуется. Карточка не передаёт точные координаты резонаторов. Она содержит номера слотов и `distance_m` — расстояние от центра портала до каждого занятого слота.

`distance_m` (с 1.3.0) — число в метрах, считается сервером по географическим координатам; на API не округляется, совпадающие позиции дают `0`. Пустой слот остаётся `null`, а не объектом с нулевой дистанцией. Это не расстояние до игрока, не длина маршрута и не расстояние до соседнего резонатора.

Редкость модов: `common`, `rare`, `very_rare`. Типы текущего каталога: `shield`, `aegis` (AXA Shield, бывший AEGIS), `link_amp`, `softbank`, `heat_sink`, `multi_hack`, `turret`, `force_amp`. Не переводите имя по виду `kind` и не заменяйте серверные характеристики статической таблицей. Числа в примере иллюстрируют один Common Portal Shield, а не неизменный баланс игры. Некоторые величины являются долями (`heat`, `stickiness`, `hit_bonus`, `drop_chance`), другие множителями или количествами; их нельзя все показывать как проценты.

Карточка не содержит инвентарь, ключи игрока, email, игровой токен, точную позицию игрока или полную историю портала. Она может быть новее последнего снимка карты: сервер не объединяет разные HTTP-запросы в один общий снимок.

## Журнал действий COMM

```http
GET /v1/intel/activity?bbox=38.95,44.95,39.05,45.05
```

Один общий журнал существующих игровых действий, без отправки сообщений. Отбираются события по **сохранённой позиции события**, а не по местонахождению игрока и не по пересечению всего линка/поля с экраном. Для графа это опорный портал события; остальные упомянутые порталы могут находиться за экраном. Закрытые для другой фракции события сервер исключает сам; одна общая вкладка не означает раскрытия всех событий всем аккаунтам.

Ответ **200**:

```json
{
  "items": [
    {
      "id": 1234,
      "kind": "capture",
      "time": "2026-10-25T09:30:00Z",
      "actor_id": "00000000-0000-4000-8000-000000000099",
      "nickname": "ExampleAgent",
      "faction": "blue",
      "portals": [
        { "id": "00000000-0000-4000-8000-000000000001", "name": "Example North", "latitude": 45.001, "longitude": 39.0 }
      ],
      "mu": null,
      "distance_m": 0
    }
  ],
  "next": "",
  "after": "opaque-value-from-server",
  "more": false
}
```

`id` — числовой int64, отдельный от UUID объектов; дедуплицируйте записи по нему. Если выбранный JSON-стек ограничивает целые числа, обеспечьте чтение int64 без потери точности. `actor_id` — UUID автора действия, не портала. `time` — RFC 3339 с часовым поясом, допускаются дробные секунды; сортировка сервера использует пару `(time,id)`. Вложенные порталы используют плоские `latitude,longitude`, в отличие от `position` в карте.

`distance_m` присутствует из общего формата журнала, но в Intel-маршруте сейчас возвращается `0`: это **не измеренное расстояние** ни до игрока, ни до центра экрана. Не показывайте его как реальную дистанцию.

| `kind` | Действие |
| --- | --- |
| `capture` | Захват портала |
| `neutralize` | Нейтрализация портала |
| `link_create` | Создание линка |
| `link_destroy` | Уничтожение линка |
| `field_create` | Создание поля |
| `field_destroy` | Уничтожение поля |
| `first_link` | Первый линк агента; видимость ограничена сервером |

Имена и координаты в событиях — исторические снимки. Упомянутый портал/объект уже может не существовать или иметь другую фракцию; обрабатывайте 404 при открытии. `mu` может стать известен позже. При отображении создания/уничтожения знак `+`/`−` добавляет клиент, само значение `mu` не является отрицательной дельтой.

### Старые и новые страницы

Параметры:

| Параметр | Назначение |
| --- | --- |
| `bbox` | Обязательная область, такой же формат, как у карты |
| `cursor` | Загрузка старых записей: значение `next` из предыдущей страницы |
| `after` | Загрузка новых записей: значение `after` из ответа |

`cursor` и `after` нельзя передавать одновременно. Их длина ограничена 800 символами каждый. Передавайте их через URL-кодирование, не разбирайте, не конструируйте и не изменяйте.

1. Первый запрос без курсоров возвращает до **50 последних событий**, от новых к старым.
2. Для прокрутки в прошлое запрашивайте `cursor=response.next`, пока `next` непустой. Порядок также от новых к старым. Не заменяйте текущий указатель новых событий полем `after` из старой страницы.
3. Для опроса новых событий сохраните `after` первого ответа. Запрос с `after` возвращает до 50 следующих событий **от старых к новым**, чтобы при большой пачке не пропустить середину.
4. После обработки новых событий сохраните возвращённый `after`. Если `more=true`, сразу дочитайте следующую новую страницу; не ждите очередного обычного интервала. Ограничивайте параллелизм и соблюдайте `Retry-After`.
5. Пустой ответ на опрос новых сохраняет `after`. Если первая область изначально пуста и `after=""`, повторяйте обычный запрос без курсора.
6. При смене bbox очистите указатели и запросите первую страницу. Курсоры подписаны и привязаны к аккаунту, фракции, направлению и точным границам. Они не подходят другому аккаунту, другой области или Android-маршруту `/v1/activity`.

В этом маршруте `next` предназначен для старых страниц. В ответе на `after` он пустой даже при `more=true`: для продолжения новой пачки используйте обновлённый **`after`**.

Это журнал с пагинацией, не WebSocket и не неизменяемый архив. Чтобы обновить отложенный MU у уже показанных последних событий, периодически перечитывайте первую страницу без курсора и объединяйте по ID. Не сдвигайте указатель непрочитанных новых событий вперёд только из-за этого перечитывания: между опросами могла накопиться пачка более 50 записей.

## Профили агентов

### Текущий пользователь

```http
GET /v1/intel/me
Authorization: Bearer <intel_token>
```

Без параметров. Пользователь определяется **только по токену**. Можно заменить email в шапке карты на `agent.nickname`, цвет взять из `agent.faction`, уровень — из `agent.effective_level`.

### Другой агент

```http
GET /v1/intel/agents/00000000-0000-4000-8000-000000000001
GET /v1/intel/agents?nickname=ExampleAgent
```

Оба запроса возвращают одну карточку в той же форме, что `me`. Нужен действующий Intel-токен. Поиск по нику — полное совпадение без учёта регистра, без подстрок, масок и выдачи списка игроков. В JavaScript используйте `new URLSearchParams({nickname})`: пробелы, кириллицу, `+`, `#` нужно кодировать. Параметр `nickname` обязателен для `/agents`, длина 1–80 Unicode-символов. Поиска email нет.

Ники из `owner`, `resonators[].owner` и `mods[].owner` карточки портала подходят для этого поиска. Если в COMM есть `actor_id`, его можно передать в `/agents/{id}`; ник также подходит. Системный автор события или прежнее имя не обязательно соответствует существующему агенту: обрабатывайте `404 agent_not_found` обычным текстом без карточки.

### Контракт карточки

| Поле | Тип / смысл |
| --- | --- |
| `kind` | `agent_profile` |
| `schema_version` | `1` — у профилей это имя, а не `schema` |
| `generated_at` | Время чтения, RFC 3339 UTC |
| `catalog_version` | Версия каталога медалей, сейчас `classic-v1` |
| `agent.id` | Публичный UUID игрока, не токен и не ID аккаунта авторизации |
| `agent.nickname` | Ник |
| `agent.faction` | `blue` или `green` |
| `agent.ap` | Серверные накопленные AP, int64 |
| `agent.earned_level` | Уровень, заработанный по AP |
| `agent.effective_level` | Действующий игровой уровень; для dev-агентов может отличаться |
| `agent.level_cap` | Текущий предел уровня, `8` |
| `agent.next_level` | `{level, required_ap, remaining_ap}` либо `null` при максимальном уровне |
| `statistics.lifetime` | Массив метрик с описанием полноты истории |
| `statistics.current` | `{status, as_of, metrics}` — фоновая проекция текущих объектов |
| `medals` | Каталог медалей с подтверждёнными наградами этого игрока |

Карточка не содержит email, аккаунтные идентификаторы, секреты, сессии, координаты агента, Hub, маршрут, остаток XM или инвентарь. Собственные ключи и сводка доступны отдельно, только через `me`. Любой авторизованный читатель видит одинаковый набор публичных полей профиля выбранного агента.

Метрика:

```json
{"code":"links_created","unit":"count","value":42,"availability":"available","coverage":"since_epoch","observed_from":"2026-10-19T00:00:00Z"}
```

`value` — int64 либо `null`. `availability`: `available`, `not_tracked`, `unavailable`. `coverage`: `since_registration`, `since_epoch`, `partial_history`, `current_snapshot`, `unknown`. `observed_from` — время начала наблюдений либо `null`. Значение `null` не заменяйте нулём; частичная история не является статистикой за всю жизнь аккаунта.

Коды накопительных метрик: `hacks`, `resonators_deployed`, `mods_deployed`, `portals_captured`, `unique_visits`, `unique_captures`, `links_created`, `fields_created`, `resonators_destroyed`, `portals_neutralized`, `links_destroyed`, `fields_destroyed`, `xm_recharged`, `xm_spent_recharging`, `longest_hack_streak`, `guardian_days`, `glyph_points`, `distance_walked`, `xm_collected`, `mu_captured`. Не все механики учитываются: проверяйте `availability`.

В текущем снимке: `active_portals`, `active_links`, `active_fields`, `resonators`, `mods`. Его статус `ready`, `building` или `unavailable`; `as_of` может быть `null`. Новое игровое действие может попасть в проекцию с задержкой.

Медаль содержит `id`, `title`, `description`, `category`, `availability`, `metric_code`, `thresholds`, `artwork_keys`, `earned_tier`, `awarded_at`, `award_origin`. `thresholds` и `artwork_keys` идут от bronze к onyx. `earned_tier`: 0 — не получена, 1–5 — подтверждённая ступень. Не вычисляйте полученную награду только по порогу: источник истины — `earned_tier`. `awarded_at` и `award_origin` могут быть `null`; происхождение награды — `observed` или `historical_import`. Категория и доступность берутся из каталога; `availability` — `active`, `historical_only` или `mechanic_missing`. Не привязывайте UI к фиксированному числу медалей.

`artwork_keys` — логические ключи ресурсов, например `medals/classic-v1/builder_bronze.png`, **не опубликованные URL картинок API**. Для веб-карты подготовьте собственный набор изображений/сопоставление ключей; не приписывайте ключу несуществующий HTTP-маршрут.

Профили отвечают с `Cache-Control: no-store`, без ETag. `404 agent_not_found` — игрока нет; `400 invalid_nickname` — неверный запрос; `503 profile_not_ready` — профиль/проекция временно недоступны (`Retry-After: 2`).

AP и счётчики передаются JSON-числами int64 без округления на сервере. JavaScript `Number` теряет точность выше `9007199254740991`. Для точной работы с такими значениями используйте JSON-парсер с поддержкой больших целых; не преобразуйте ответ в `Number` до форматирования. Это относится и к MU.

## Личные ключи и инвентарь

### Ключи по порталам

```http
GET /v1/intel/me/keys
GET /v1/intel/me/keys?cursor=<next_cursor>
```

Пример с вымышленными данными:

```json
{
  "schema": 1,
  "items": [{
    "portal_id": "00000000-0000-4000-8000-000000000001",
    "name": "Example North",
    "position": {"latitude": 45.001, "longitude": 39.0},
    "quantity": 5,
    "available_quantity": 2,
    "contained_quantity": 3
  }],
  "next_cursor": "",
  "server_time": "2026-10-26T06:00:00Z"
}
```

| Поле | Смысл |
| --- | --- |
| `portal_id`, `name`, `position` | Портал ключа, в том числе за пределами видимой карты |
| `quantity` | Все ключи этого портала у владельца сессии |
| `available_quantity` | Ключи вне капсул, доступные для обычного расходования |
| `contained_quantity` | Ключи внутри принадлежащих ему капсул, включая MUFG |
| `next_cursor` | UUID последнего портала страницы; пустая строка — конец |
| `server_time` | Время чтения страницы, не снимок всей последовательности страниц |

Всегда `quantity = available_quantity + contained_quantity`. Предметы на земле и в капсулах других игроков не учитываются. ID и названия капсул не выдаются. Запрос не меняет предметы и не извлекает их из капсул. Параметров выбора чужого пользователя нет.

Размер страницы фиксирован: максимум **128 порталов**, порядок по UUID. Передавайте `next_cursor` без изменений; неверный формат — `400 invalid_cursor`. Чтобы утверждать «ключа нет», сначала загрузите все страницы. Во время обхода инвентарь может измениться: это последовательность актуальных страниц, не закреплённый общий снимок. Периодически перечитывайте набор с первой страницы и заменяйте его целиком; при выходе очищайте личный слой карты.

Для подсветки «есть любой ключ» используйте `quantity > 0`. Для подсказки «есть доступный ключ для линка» — `available_quantity > 0`. Наличие ключа и дальность не гарантируют возможность построения: нужны фракция, полная установка резонаторов, свободный исходящий слот, отсутствие запрещённых пересечений и другие игровые условия. Intel API только читает и не выполняет игровую операцию.

### Сводка инвентаря

```http
GET /v1/intel/me/inventory
```

```json
{
  "schema": 1,
  "items": [{"kind":"xmp","level":3,"quantity":9}],
  "server_time": "2026-10-26T06:00:00Z"
}
```

Одна строка на сочетание `kind` + `level`, отсортировано по этим полям; отсутствующих видов нет, `items` может быть `[]`. Нелевелируемые предметы имеют `level: 0`. `quantity` — единое количество всех предметов этого вида/уровня: свободных и внутри собственных капсул, включая MUFG. Разделения на содержимое капсул и свободные предметы здесь нет. Капсулы считаются предметами своего вида, их содержимое — предметами соответствующего вида. Строка `kind: "key"` содержит общую сумму ключей, детализация по порталам — в `/me/keys`. Неизвестный новый `kind` обрабатывайте без сбоя.

Это сводка, а не список ID экземпляров или операций. Выдаётся только владельцу токена. `Cache-Control: no-store` для обоих личных маршрутов; не сохраняйте ответы в общем HTTP/CDN-кеше и очищайте данные при смене аккаунта. Пароль после входа не храните и не логируйте; read-only токен даёт доступ к личному инвентарю владельца, поэтому также является секретом.

## Дальность исходящего линка

Ответ существующего `GET /v1/intel/portals/{id}` дополнен объектом `planning`:

```json
{"fully_deployed":true,"max_link_range_m":655360,"incoming_links":2,"outgoing_links":3,"outgoing_limit":8}
```

`max_link_range_m` — максимальная длина **нового исходящего линка из этого портала**, в метрах, с учётом живых резонаторов и серверных эффектов Link Amp / SoftBank. Это не длина существующего линка и не радиус доступа игрока. Расчёт использует дробное среднее уровней всех восьми резонаторов, без округления до отображаемого целого уровня портала.

Если живых резонаторов меньше восьми: `fully_deployed: false`, `max_link_range_m: 0`. `incoming_links` и `outgoing_links` — текущие числа линков, `outgoing_limit` учитывает серверные моды. Проверка дальности относится к исходному порталу; направление из A в B и из B в A может давать разный результат. Эти данные — помощь в планировании, не гарантия возможности игровой операции.

## Мировой счёт MU

```http
GET /v1/intel/score
```

```json
{
  "schema": 1,
  "balance": {
    "status": "ready",
    "scope": "world",
    "epoch_id": "00000000-0000-4000-8000-000000000099",
    "as_of": "2026-10-26T06:00:00Z",
    "revision": 7,
    "enlightened_mu": 300,
    "resistance_mu": 700,
    "enlightened_percent": 30,
    "resistance_percent": 70,
    "active_fields": 2,
    "processed_fields": 2,
    "pending_fields": 0,
    "unresolved_fields": 0
  }
}
```

Мировой счёт — MU **действующих полей** обеих фракций в активной MU-эпохе, а не сумма личных достижений и не сумма полей текущего viewport. `enlightened` соответствует `green`, `resistance` — `blue`. Данные читаются из готового фонового снимка; запрос не запускает расчёт населения или обход всей карты.

| `balance.status` | Как отображать |
| --- | --- |
| `ready` | Рассчитанный баланс; проценты доступны при положительной сумме MU |
| `empty` | В текущем снимке нет активных полей; проценты `null`, не 50/50 |
| `partial` | Часть полей ещё считается или не определена; суммы предварительные, проценты `null` |
| `stale` | Снимок старше двух минут; показать время и устаревание, проценты `null` |
| `disabled` | MU-эпоха не включена; численные поля, время, ID и revision — `null` |
| `unavailable` | Эпоха есть, готового снимка ещё нет; поля также `null` |

`as_of` — время фонового снимка, `revision` меняется при изменении его содержимого. `processed_fields` — число рассчитанных действующих полей; `pending_fields` — ожидающих расчёта, `unresolved_fields` — неразрешённых. Не заменяйте неизвестные суммы нулями. Поддерживаются ETag/304 и gzip; разумное обновление — раз в 30–60 секунд с паузой для скрытой вкладки. Read-only токен обязателен и здесь.

## Рейтинг агентов

```http
GET /v1/intel/rating?kind=links
GET /v1/intel/rating?kind=fields&cursor=<next_cursor>
```

Intel-токен обязателен. По 25 строк на странице; `next_cursor: null` означает конец. `kind=links` — действующие линки (`active_links`, единица `count`), `kind=fields` — MU действующих полей (`active_mu`, единица `mu`), как в игровом клиенте. Ответ содержит `entries` (место, ник, фракция, ID, значение, текущий уровень), собственную строку `self`, метаданные `snapshot`, `levels_as_of` и `next_cursor`.

Пагинация использует один опубликованный снимок до 10 минут. Курсоры вкладок несовместимы; на `410 leaderboard_snapshot_expired` начать заново без курсора. Уровни читаются из текущего состояния отдельно от снимка, могут быть `null`. Ответ — `no-store`, без ETag. Лимит общий с остальным Intel API: 120 запросов/минуту на пользователя. Рейтинг не предоставляет региональные фильтры или историю.

Полный самостоятельный контракт, все поля, пример ответа, ошибки и JavaScript: [NETGRESS_INTEL_RATING.md](NETGRESS_INTEL_RATING.md). Для чтения в браузере — [NETGRESS_INTEL_RATING.html](NETGRESS_INTEL_RATING.html).

## Кеширование и обновление

### HTTP

Карта, карточка портала, COMM и мировой счёт поддерживают `private, no-cache` и ETag. **Исключение:** профили, рейтинг, личные ключи и инвентарь имеют `no-store`, без ETag/304.

Успешные GET-ответы карты, карточки и COMM возвращают `ETag` и `Cache-Control: private, no-cache`. Для **того же URL, аккаунта и сессии** можно передать:

```http
If-None-Match: "previous-etag"
```

Если представление не изменилось, сервер вернёт **304 без тела**. Используйте сохранённый JSON; не вызывайте `response.json()` для 304. `no-cache` разрешает хранение с повторной валидацией, а не означает запрет локального хранения. Не смешивайте такие ответы в общем межпользовательском кеше.

ETag вычисляется после чтения актуального состояния. Ответ 304 сокращает передачу данных, но **не является бесплатным опросом**: запрос всё равно учитывается в лимите и читает базу. Поддерживается gzip; браузер обычно согласует его сам, для curl используйте `--compressed`.

### Поведение карты

Рекомендуемый стартовый режим клиента, а не обязательное серверное правило:

- Обновлять карту после `moveend`/смены zoom с debounce примерно 350 мс.
- Отменять старый запрос через `AbortController` и дополнительно проверять номер поколения запроса: запоздалый ответ не должен возвращать прежнюю область на экран.
- Повторять чтение видимой карты и COMM примерно раз в 30 секунд; при скрытой вкладке приостанавливать опрос, при возврате обновлять данные.
- Загружать карточку по выбору портала, кешировать ненадолго, ограничивать число одновременных запросов и размер кеша.
- На ошибке сети/503 оставлять последнее представление с пометкой о давности; на 401 очищать сессию и показывать вход.
- При смене аккаунта очищать карту, COMM, запросы и кеш, включая ETag.

Ниже самостоятельный JavaScript-пример получения снимка. Он работает в разрешённом браузерном origin либо в среде с `fetch`, где браузерный CORS не применяется. Сам по себе код не открывает доступ новому веб-домену.

```javascript
const API = 'https://api.netgress.ru';

async function readMap(token, bbox, zoom, { signal, cached } = {}) {
  const params = new URLSearchParams({ bbox: bbox.join(','), zoom: String(zoom) });
  const url = `${API}/v1/intel/map?${params}`;
  const previous = cached?.url === url && cached?.token === token ? cached : null;
  const headers = { Authorization: `Bearer ${token}`, Accept: 'application/json' };
  if (previous?.etag) headers['If-None-Match'] = previous.etag;

  const response = await fetch(url, {
    headers, signal, credentials: 'omit', cache: 'no-cache',
    redirect: 'error', referrerPolicy: 'no-referrer'
  });
  if (response.status === 304 && previous) return previous;
  if (!response.ok) {
    const body = await response.json().catch(() => null);
    const error = new Error(body?.error?.message || `HTTP ${response.status}`);
    error.status = response.status;
    error.code = body?.error?.code;
    error.retryAfter = Number(response.headers.get('Retry-After')) || 30;
    throw error;
  }
  const data = await response.json();
  if (data.schema !== 1) throw new Error('Unsupported map schema');
  return { url, token, etag: response.headers.get('ETag'), data };
}

// Внутри обработчика движения карты:
let generation = 0;
let active;
let cachedMap;

async function updateViewport(token, bbox, zoom) {
  const current = ++generation;
  active?.abort();
  active = new AbortController();
  try {
    const result = await readMap(token, bbox, zoom, {
      signal: active.signal, cached: cachedMap
    });
    if (current !== generation) return;
    cachedMap = result;
    renderMap(result.data); // функция вашего картографического движка
  } catch (error) {
    if (current !== generation || error.name === 'AbortError') return;
    showMapError(error); // обработайте 401, 429/Retry-After и временные ошибки
  }
}
```

Кеш в примере находится в памяти и содержит секрет; не сериализуйте его в журнал. При выходе/смене аккаунта увеличьте `generation`, отмените `active` и очистите `cachedMap`, чтобы ответ прежней сессии не применился к новой.

## Ошибки и ограничения

Обычный JSON-формат ошибки:

```json
{
  "error": {
    "code": "invalid_bbox",
    "message": "Некорректная область карты"
  }
}
```

Ориентируйтесь на HTTP-статус и `error.code`, а не на точный текст `message`. Прокси или сетевой сбой могут вернуть не-JSON ответ.

| HTTP | Типичные коды/случаи | Действие клиента |
| --- | --- | --- |
| 400 | `invalid_input`, `invalid_bbox`, `invalid_zoom`, `invalid_cursor` | Исправить запрос; курсор другой области не переиспользовать |
| 401 | `invalid_credentials` при входе, `unauthorized` при чтении | Вход: сообщить об ошибке; чтение: удалить недействительную сессию |
| 403 | `origin_denied` | Проверить согласование браузерного origin; повторный вход не исправит CORS |
| 404 | `portal_not_found` | Портал удалён/не найден; закрыть или обновить карточку |
| 429 | `rate_limited`, `auth_busy`, общие ограничения | Выдержать `Retry-After`, снизить частоту/параллелизм |
| 500 | `internal_error` | Не считать ответ данными; ограниченный повтор позже |
| 503 | `intel_unavailable`, `auth_unavailable`, `logout_unavailable` | Временная ошибка; не стирать действующий токен только из-за неё |

Иногда обрабатываемый как ID портала некорректный UUID также даёт 404. Несуществующий HTTP-маршрут не обязан возвращать JSON в этом формате.

### Бюджеты

- Intel-маршруты суммарно ограничены **120 авторизованными запросами за минутное окно на пользователя** в текущем экземпляре API. Счётчик общий для разных Intel-токенов одного пользователя; не рассчитывайте получить отдельный бюджет на каждый токен. В него входят карта, карточки, COMM и выход; повторная валидация и ошибочные параметры после авторизации тоже расходуют бюджет.
- Дополнительно действуют общие серверные ограничения по IP и одновременной нагрузке. `Retry-After` может различаться; читайте заголовок, а не подставляйте всегда 60 секунд.
- Для входа действуют отдельные ограничения: 10 попыток за 15 минут на email и 120 auth-запросов за 15 минут на IP; возможен отказ занятого обработчика паролей. Не выполняйте вход перед каждым чтением.
- Контекст защищённого Intel-запроса ограничен 8 секундами; для авторизации используется отдельный контекст до 18 секунд. Это не обещание SLA: сеть и прокси могут завершить запрос раньше или позже.
- Выдача мира не имеет потоковых подписок, глобального курсора изменений, endpoint для выгрузки всей базы или гарантии полного снимка в одном запросе.

## Порядок реализации клиента

1. Согласуйте браузерный origin и способ хранения сессии.
2. Реализуйте вход через `/v1/auth/intel/login`, обработку 401 и явный выход.
3. Преобразуйте bounds своего движка в bbox с нормализацией 180-го меридиана; передавайте целый zoom 0–22.
4. Рисуйте порталы по ID, линки по вершинам и `source_portal_id`, поля по трём вершинам. Обрабатывайте LOD и неполноту массивов независимо.
5. По клику получайте карточку; корректно обрабатывайте пустые слоты, `owner: null`, отсутствие фото и `mu: null`.
6. Добавьте COMM с отдельными курсорами старых и новых событий, сбросом по bbox и дедупликацией.
7. Добавьте отмену запросов, защиту от старых ответов, ETag, ограниченный кеш и соблюдение лимитов.
8. Проверьте пустую область, плотную область с `truncated`, zoom 14→15, 180-й меридиан, отзыв токена, 429/503, удалённый портал и пачку более 50 новых событий.

## Граница публичного API и реестр остальных маршрутов

Этот справочник полностью описывает **все 12 маршрутов API для сторонних карт**, включая авторизацию и выход. Остальные маршруты сервера относятся к игровому клиенту, защищены отдельной игровой авторизацией и политикой client-security; Intel-токен к ним не подходит. Разрешение CORS для карты распространяется только на `/v1/intel/*` и `/v1/auth/intel/login`.

Полный индекс остальных HTTP-маршрутов сервера, с группами и ссылками на действующие контракты: [NETGRESS_HTTP_ENDPOINTS.md](NETGRESS_HTTP_ENDPOINTS.md). Не используйте игровой login или чужие игровые сессии для обхода Intel-ограничений.
