# Идеи фич

Отложенные идеи. Две группы:
- **А** — можно сделать на данных, которые API отдаёт уже сейчас (контракт 1.1.0);
- **Б** — нельзя сделать, пока API их не отдаёт. Формат записи: «если появится
  эндпоинт X → можно сделать фичу Y».

Изменения контракта сверяем с `docs/NETGRESS_MAP_API.md`.

# А. На текущих данных

А1–А3 строятся на ленте COMM (`GET /v1/intel/activity`), которую клиент уже
загружает для видимой области.

## А0. Панель «Слои и фильтры»: компактная раскладка
Делаем до А1: трекер добавляет в панель новую строку, а панель и так длинная.
Цель: около 10 строк вместо 25, панель помещается на телефоне в обеих
ориентациях.

```
Подложка  [Yandex ▾]       Уровни [Нейтр.▾]–[8▾]
Подсветка порталов                RES  ENL
  Верх  [Нет ▾]            Порталы ☑    ☑
  Низ   [Нет ▾]            Линки   ☑    ☑
  Текст [Нет ▾]            Поля    ☑    ☑
Поля  [Площадь][MU]        Агенты  ☑    ☑
```

- **Подложка** — выпадающий список вместо радиокнопок.
- **Подсветка полей** — два переключателя в одну строку.
- **Уровни** — диапазон «от–до», нейтральный портал считается уровнем 0
  («Нейтр.»). Заменяет чекбокс «Нейтральные» и 8 чекбоксов уровней. Если «от»
  больше «до», второе значение подтягивается к первому.
- **Матрица фракций**: колонки RES / ENL, строки — порталы, линки, поля, агенты
  (А1). Каждая ячейка переключается отдельно; нажатие на заголовок колонки
  переключает всю фракцию, на подпись строки — весь тип. По умолчанию всё
  включено. Это только фильтр отображения, игровую механику он не меняет.
- **Перенос сохранённых настроек**: `neutral: false` → «от 1»; уровни → диапазон
  от минимального до максимального включённого; `res`/`enl: false` → колонка
  выключена; `links`/`fields: false` → строка выключена.

## А1. Трекер агентов
Пины агентов на карте по их последним действиям в COMM и пунктирный след между
точками. Поведение повторяет привычный трекер из IITC.

**Данные**
- Только то, что COMM уже загрузил: своих запросов трекер не делает, старые
  страницы принудительно не догружает.
- Отдельное хранилище: события по `id`, сгруппированные по `actor_id`. При смене
  области COMM очищает свой список, а трекер свои данные сохраняет и продолжает
  накапливать.
- Окно 3 часа, всё старше отбрасывается.
- Место агента — `portals[0]` у `capture`, `neutralize`, `link_create`,
  `field_create`, `first_link`. **Уточнить у разработчика**, что для линка и поля
  это портал, у которого стоит агент.
- `link_destroy` / `field_destroy` пропускаем: по ним не понять, где стоял агент.
- События одного агента с одинаковым временем склеиваются в одну точку (центр
  порталов). Повтор на том же портале не создаёт новую точку, а только обновляет
  её время.

**Отрисовка**
- Пин цвета фракции в последней точке. Прозрачность падает с давностью:
  от 1 у свежих до 0.3 к границе 3 часов.
- След — пунктир между точками одним контрастным цветом; 4 отрезка по давности,
  старые тоньше и бледнее. Линии не кликаются.
- Наведение (десктоп): «ник, N мин назад».
- Нажатие: окно с ником (ссылка на профиль), временем, порталом и до 10
  предыдущих мест с временем. Клик по порталу открывает карточку (404 обрабатываем).
- Пины в одной точке не должны перекрывать друг друга: раскрывать их или
  показывать список.
- Ниже зума 9 трекер скрыт (данные не стираются), строка «Агенты» в матрице
  серая с подсказкой «Приблизьте карту».

**Включение** — строка «Агенты» в матрице фракций (А0), по умолчанию включена.

**Фокус на агенте** — в карточке агента (её открывает клик по нику):
- есть данные → кнопка «Показать на карте · N мин назад»: центрирует карту на
  последней точке и выделяет его след, остальные приглушает; по желанию лента
  COMM фильтруется по `actor_id` (снимается крестиком в шапке ленты);
- нет данных → серая строка «Нет действий в загруженной ленте за 3 ч».

## А2. История портала в карточке
Последние события с этим порталом из загруженной ленты области. Это не полная
история: её API не отдаёт.

## А3. Сигнал по избранному
Событие на избранном портале (захват, нейтрализация) → отметка в ленте и бейдж
на кнопке избранного.

Ограничения данных COMM, которые надо соблюдать:
- `distance_m` в событиях всегда `0` — это не расстояние, не показывать.
- Позиция события — опорный портал; остальные порталы события могут быть за экраном.
- Имена и координаты в событиях исторические: портал мог исчезнуть или сменить
  фракцию; открытие обрабатывает 404.
- Бюджет 120 запросов/мин общий для карты, карточек и COMM.

## А6. Планирование линков с учётом ключей
В рисовании: подсказать, какие линки реально можно построить — есть свободный
ключ к целевому порталу (`available_quantity > 0`), хватает дальности исходного
(`planning.max_link_range_m`), есть свободный исходящий слот (`outgoing_limit`).
Это подсказка, а не гарантия: пересечения и прочие игровые условия API не
проверяет.

## А7. Auto draw по избранному
Как «Auto draw» закладок в IITC: отметить в окне избранного 2 или 3 портала —
и в рисование добавляется линия или треугольник по ним (вершины точно на
порталах). Быстрый способ набросать план из заранее собранной группы целей.

# Б. Ждут появления эндпоинтов в API

## Б1. Подача порталов (кандидаты)

**Если** появится эндпоинт подачи кандидатов (напр. `POST /v1/intel/portals/submissions`
с координатами/названием/фото), **то** можно вернуть инструмент подачи:
- Кнопка-инструмент: постановка маркера на карте, форма названия/фото, отправка.
- Список своих заявок и их статусов.

Статус: **плагин пока отключён** (в игре подачи ещё нет). Автор подтвердил, что
обязательно добавит подачу порталов — тогда включим инструмент обратно.

> Напоминание о границах проекта: добавление подачи порталов останется в рамках
> read-only для чтения карты + один явный пользовательский submit-экшен. Любое
> расширение за пределы «карта + подача» обсуждаем отдельно.
