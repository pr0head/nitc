# Будущие фичи — ждут появления эндпоинтов в API

Идеи, которые сейчас нельзя реализовать: текущий read-only Map API их не отдаёт.
Фиксируем здесь, чтобы не забыть и вернуться, когда API расширится. Каждая запись:
«если появится эндпоинт X → можно сделать фичу Y».

Отслеживаемые изменения контракта сверяем с `docs/NETGRESS_MAP_API.md`.

---

## 1. Карточка игрока (профиль, медали, AP) — ВАЖНО

**Если** появится интел-эндпоинт профиля агента (напр. `GET /v1/intel/agents/{id}`
или `.../profile/{nickname}`), отдающий имя, фракцию, уровень, AP, медали и статы,
**то** можно сделать:
- Карточку игрока по клику на никнейм (в карточке портала, в резонаторах/модах, в COMM).
- Всплывающую мини-справку об агенте рядом с его объектами.
- Бейдж фракции/уровня автора события в ленте COMM.

Статус: **очень ждём.** Автор рассматривает добавление. До этого — ника достаточно
для отображения текстом; кликабельность профиля подключим, когда появится эндпоинт.

Готовые точки подключения: в карточке портала ники владельца, резонаторов и модов
сейчас обычный текст — сделать их ссылками на карточку игрока.

## 1a. Собственный профиль (`me`)

**Если** появится профиль текущего пользователя (ник, фракция, уровень), **то**:
- Плашка слева сверху: ник в цвете фракции вместо email.
- Строка «Урон» в карточке портала: ответный удар портала по *мне* есть только у
  чужой фракции — без своей фракции «враждебность» не определить. Плюс модель
  турелей/форс-ампов (частота, урон) по их серверной спецификации.

## 2. Инвентарь и ключи — ВАЖНО (для планирования)

**Если** появится эндпоинт инвентаря/ключей текущего пользователя (напр.
`GET /v1/intel/me/keys` → `[{portal_id, quantity}]`), **то** можно сделать:
- Подсветку порталов, на которые у меня есть ключ (и их количество).
- Фильтр «есть ключ» / «нет ключа» на карте.
- Планирование линков с учётом наличия ключей (какие связи я реально могу построить).
- Индикатор дальности/достижимости при планировании полей.

Статус: **очень ждём.** Для карты и планирования это крайне удобно. Релизнём фичу,
как только появится источник данных по ключам.

Готовые точки подключения: строка «Ключи» в карточке портала, вариант «Ключи» в
подсветке (текст на портале).

## 3. Подача порталов (кандидаты)

**Если** появится эндпоинт подачи кандидатов (напр. `POST /v1/intel/portals/submissions`
с координатами/названием/фото), **то** можно вернуть инструмент подачи:
- Кнопка-инструмент: постановка маркера на карте, форма названия/фото, отправка.
- Список своих заявок и их статусов.

Статус: **плагин пока отключён** (в игре подачи ещё нет). Автор подтвердил, что
обязательно добавит подачу порталов — тогда включим инструмент обратно.

> Напоминание о границах проекта: добавление подачи порталов останется в рамках
> read-only для чтения карты + один явный пользовательский submit-экшен. Любое
> расширение за пределы «карта + подача» обсуждаем отдельно.
