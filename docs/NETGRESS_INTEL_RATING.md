# Рейтинг агентов: GET /v1/intel/rating

Контракт **1.2.0**, 26 октября 2026. Этот документ описывает только новый маршрут рейтинга для сторонних карт Netgress. Основной адрес: `https://netgress.glubina.org`. Альтернативный адрес: `https://ingress.worldofton.ru`.

## Запрос

```http
GET /v1/intel/rating?kind=links
Authorization: Bearer <intel_token>
```

Следующая страница:

```http
GET /v1/intel/rating?kind=links&cursor=<next_cursor>
Authorization: Bearer <intel_token>
```

| Параметр | Обязателен | Значение |
| --- | --- | --- |
| `kind` | Да | `links` или `fields`, в нижнем регистре |
| `cursor` | Нет | Непрозрачная строка `next_cursor` предыдущего ответа той же вкладки |

Размер страницы фиксирован: **до 25 агентов**. Параметра настройки `limit` в контракте нет. Первая страница читается без `cursor`. Это мировой рейтинг игроков; фильтра по региону, фракции или периоду здесь нет.

Для запроса нужен обычный read-only Intel-токен, выданный `POST /v1/auth/intel/login`. Игровой токен не подходит. Разрешённые браузерные источники: `https://pr0head.github.io`, `https://intel.ingress.com`, `https://intel-x.ingress.com`. Используйте `credentials: 'omit'`; cookies не применяются.

## Что означают вкладки

| `kind` | `metric` в ответе | `unit` | Значение `score` |
| --- | --- | --- | --- |
| `links` | `active_links` | `count` | Количество действующих линков агента |
| `fields` | `active_mu` | `mu` | MU действующих полей агента, учтённые фоновым расчётом |

Это **те же показатели и опубликованные снимки**, которые читает игровой клиент во вкладках «Линки» и «Поля». «Поля» означает рейтинг по MU, а не по количеству полей. Накопленные за всю историю `links_created` / `fields_created` здесь не используются. При уничтожении объектов их вклад после фонового обновления исчезает из рейтинга.

MU ещё не рассчитанных полей не следует считать нулевым населением. Снимок рейтинга отображает уже учтённые значения; общий статус расчёта мирового баланса можно отдельно получить через `/v1/intel/score`. Сам маршрут рейтинга не запускает расчёты и не пересчитывает граф на запросе.

## Ответ 200

Ниже синтетический пример последней страницы с одной строкой. Реальный ответ может содержать до 25 строк.

```json
{
  "kind": "leaderboard",
  "schema_version": 1,
  "rating_kind": "links",
  "metric": "active_links",
  "unit": "count",
  "snapshot": {
    "id": "00000000-0000-4000-8000-000000000100",
    "as_of": "2026-10-26T12:00:00Z",
    "published_at": "2026-10-26T12:00:01Z",
    "expires_at": "2026-10-26T12:10:02Z",
    "coverage_note": "По подтверждённым действиям; история до начала учёта может быть неполной"
  },
  "entries": [
    {
      "id": "00000000-0000-4000-8000-000000000001",
      "nickname": "ExampleAgent",
      "faction": "blue",
      "rank": 1,
      "score": 42,
      "is_self": true,
      "level": 8
    }
  ],
  "self": {
    "id": "00000000-0000-4000-8000-000000000001",
    "nickname": "ExampleAgent",
    "faction": "blue",
    "status": "ranked",
    "rank": 1,
    "score": 42,
    "level": 8
  },
  "next_cursor": null,
  "levels_as_of": "2026-10-26T12:00:02Z"
}
```

### Строка рейтинга

| Поле | Тип / назначение |
| --- | --- |
| `id` | UUID агента; использовать для клика в профиль |
| `nickname` | Ник на момент снимка рейтинга |
| `faction` | `blue` или `green`, на момент снимка |
| `rank` | Положительное целое место, начиная с 1 |
| `score` | Неотрицательное целое int64, количество линков или MU по `unit` |
| `is_self` | Эта строка принадлежит владельцу текущего токена |
| `level` | Текущий действующий уровень 1–8; `null`, если состояние игрока недоступно |

Строки идут по месту. Положительные результаты сортируются по убыванию значения; при равном значении используется UUID агента по возрастанию. Места последовательные и уникальные даже при равных значениях. Игроки с нулевым или неизвестным результатом не попадают в `entries`.

Чтобы открыть карточку по клику на ник:

```http
GET /v1/intel/agents/00000000-0000-4000-8000-000000000001
Authorization: Bearer <intel_token>
```

Формат профиля описан в [общем справочнике](NETGRESS_API_REFERENCE.html#профили-агентов). Никнеймы выводите текстом, а не как HTML. Агент мог быть удалён после публикации снимка: профиль может ответить `404 agent_not_found`, а `level` — стать `null`.

### Собственная строка self

`self` присутствует независимо от того, попал ли текущий игрок на загруженную страницу. Она содержит `id`, `nickname`, `faction`, `status`, `rank`, `score`, `level`.

| `self.status` | Смысл |
| --- | --- |
| `ranked` | Есть положительный результат и место в этом снимке |
| `unranked` | Известен результат 0, места нет: `rank: null`, `score: 0` |
| `not_tracked` | Нет учтённого результата/строки в снимке: `rank: null`, `score: null` |

Не заменяйте неизвестное значение нулём. Если игрок зарегистрировался после публикации снимка, `self` может использовать текущие ник/фракцию с `not_tracked` до следующего обновления.

## Снимок и пагинация

`next_cursor` — строка, если есть ещё данные; **`null` — конец списка**. Не путайте с ключами `/v1/intel/me/keys`, где конец обозначен пустой строкой.

Курсор нужно передавать без разбора и изменений, URL-кодируя его обычным `URLSearchParams`. Он привязан к метрике и одному опубликованному `snapshot.id`. У каждой вкладки должен быть свой список и курсор. Курсор `links` нельзя использовать для `fields`.

Все страницы одной цепочки используют тот же снимок: места, значения, ники и фракции не перескакивают при публикации нового поколения. Первый запрос без курсора получает актуальный опубликованный снимок. Фоновое обновление не обязано происходить сразу после каждого действия.

Срок курсора — около **10 минут от первой страницы**, точный предел указан в `snapshot.expires_at`; последующие страницы не продлевают его. Если курсор истёк или его снимок уже недоступен, сервер возвращает `410 leaderboard_snapshot_expired`. Очистите список этой вкладки и загрузите первую страницу без курсора. Не дописывайте новую первую страницу к старому списку.

`as_of` — время данных снимка; `published_at` — время публикации. **Уровни отдельно читаются из текущего состояния** для максимум 25 строк и `self`; время этого чтения — `levels_as_of`. При повышении уровня он может обновиться между страницами, хотя сам рейтинг остаётся привязанным к снимку. Исторический уровень на момент снимка не выдаётся.

Пустой рейтинг — успешный ответ `200` с `entries: []`, `next_cursor: null` и собственной строкой. Отсутствие готового снимка — отдельная ошибка `503`.

## Кеширование, лимиты и ошибки

Ответ имеет `Cache-Control: no-store`; ETag/304 не используются, поскольку есть `self` и `is_self`. При выходе или смене аккаунта очищайте рейтинг в интерфейсе. Секретный токен не включайте в URL, логи или публичный код.

Общий лимит Intel API: **120 запросов в минуту на владельца токена**, совместно с картой, COMM и остальными маршрутами. Не запрашивайте отдельно профиль каждого игрока ради уровня: уровень уже включён. Профиль загружайте по клику. На скрытой вкладке остановите периодический опрос; рейтинг можно перечитывать по открытию окна и по кнопке обновления.

Общая форма ошибки:

```json
{"error":{"code":"invalid_rating_kind","message":"Выберите рейтинг links или fields"}}
```

| HTTP | Код | Действие клиента |
| --- | --- | --- |
| 400 | `invalid_rating_kind` | Указать `kind=links` или `kind=fields` |
| 400 | `invalid_cursor` | Неверный/чужой для вкладки курсор; начать с первой страницы |
| 401 | `unauthorized` | Сессия отсутствует, недействительна или отозвана; повторить вход |
| 403 | `origin_denied` | Источник страницы не разрешён CORS |
| 410 | `leaderboard_snapshot_expired` | Очистить текущую вкладку рейтинга и запросить её первую страницу |
| 429 | `rate_limited` | Соблюсти `Retry-After` (обычно 60 секунд) |
| 503 | `leaderboard_not_ready` | Снимок ещё не готов; повторить позднее, `Retry-After: 2` |
| 503 | `profile_not_ready` / `intel_unavailable` | Временная недоступность чтения/авторизации; повторить позднее |

JSON-счётчики передаются как int64. JavaScript `Number` точен только до `9007199254740991`; при больших MU используйте JSON-парсер, сохраняющий большие целые. Сервер не преобразует большие числа в строки и не округляет их.

## Минимальный пример JavaScript

```javascript
async function loadRating(token, kind, cursor = null, signal) {
  const query = new URLSearchParams({ kind });
  if (cursor) query.set('cursor', cursor);
  const response = await fetch(
    `https://netgress.glubina.org/v1/intel/rating?${query}`,
    {
      headers: { Authorization: `Bearer ${token}` },
      credentials: 'omit',
      cache: 'no-store',
      signal
    }
  );
  if (!response.ok) {
    const body = await response.json();
    throw Object.assign(new Error(body.error?.message || 'Rating unavailable'), {
      status: response.status,
      code: body.error?.code
    });
  }
  // Для int64 выше Number.MAX_SAFE_INTEGER замените response.json()
  // парсером с сохранением больших целых.
  return response.json();
}

const first = await loadRating(token, 'links');
// Показать first.entries, отдельно first.self.
// Кнопка «Загрузить ещё» видима, пока next_cursor !== null.
if (first.next_cursor !== null) {
  const more = await loadRating(token, 'links', first.next_cursor);
  // Дописать more.entries к списку той же вкладки.
}
```

При переключении вкладки отменяйте старый запрос через `AbortController` либо проверяйте, что его ответ всё ещё относится к выбранной вкладке. Для новой загрузки без курсора заменяйте список целиком.
